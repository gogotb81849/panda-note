### 问题A：登录按钮点击无反应（2026-06-20）

**问题描述：**
- 用户点击登录页面上的"登录"按钮，页面没有任何反应
- 没有跳转到首页，也没有显示错误提示
- 浏览器控制台显示 `[Vue Router warn]: No match found for location with path "/api/version/info"`

**排查过程：**
1. **前端日志分析** - 前端PM2日志显示 `/api/version/info` 被Vue Router当作前端路由处理，而不是代理到后端
2. **后端日志分析** - 后端PM2日志显示大量 `Error: CORS策略拒绝该来源` 错误
3. **配置检查** - 发现后端 `.env` 中 `FRONTEND_URL` 只配置了 `localhost:3000,localhost:3001`
4. **访问方式确认** - 服务器没有安装Nginx，用户直接通过 `http://106.14.57.62:3000` 访问
5. **根本原因定位** - `http://106.14.57.62:3000` 不在CORS白名单内，导致所有API请求被后端拒绝

**根本原因：**
1. **CORS白名单不完整** - 后端CORS配置只包含localhost，没有包含服务器IP地址
2. **前端环境变量缺失** - PM2启动前端时没有设置 `NUXT_PUBLIC_API_BASE`，导致SSR模式下API请求路径不正确
3. **前端代理配置问题** - Nuxt的 `routeRules` 只在构建时生效，通过PM2直接启动时不会处理代理

**解决方案：**

**步骤1：修改后端CORS白名单**
```bash
# 服务器端执行
sed -i 's/FRONTEND_URL=.*/FRONTEND_URL="http:\/\/localhost:3001,http:\/\/localhost:3000,http:\/\/106.14.57.62:3000,http:\/\/106.14.57.62:3001"/' /www/wwwroot/nav-log-system/backend/.env

# 重启后端使配置生效
pm2 restart nav-log-backend
```

**步骤2：配置前端环境变量**
```bash
# 停止并删除旧的前端进程
pm2 stop nav-log-frontend
pm2 delete nav-log-frontend

# 带环境变量重新启动
cd /www/wwwroot/nav-log-system/frontend
NUXT_PUBLIC_API_BASE=http://localhost:3002/api pm2 start .output/server/index.mjs --name nav-log-frontend --env NODE_ENV=production --env NUXT_PUBLIC_API_BASE=http://localhost:3002/api

# 保存PM2配置
pm2 save
```

**步骤3：更新部署脚本**
修改 `deploy/deploy_build_to_server.py`，确保后续部署自动包含环境变量：
```python
# 6. 启动新前端（带环境变量）
print("\n6. 启动新前端...")
run(ssh, f'cd {DEPLOY_DIR} && pm2 start .output/server/index.mjs --name nav-log-frontend --env NODE_ENV=production --env NUXT_PUBLIC_API_BASE=http://localhost:3002/api')
run(ssh, 'pm2 save')
```

**验证方法：**
```bash
# 检查后端日志，确认没有CORS错误
pm2 logs nav-log-backend --lines 50 --nostream | grep CORS

# 测试登录API是否正常响应
curl -s -X POST http://106.14.57.62:3002/api/auth/login -H 'Content-Type: application/json' -H 'Origin: http://106.14.57.62:3000' -d '{"username":"gogotb","password":"123456"}'
```

**解决结果：** ✅ 登录按钮现在有响应，CORS错误消失

**避免措施：**
1. 每次修改服务器IP或域名时，同步更新 `FRONTEND_URL` 环境变量
2. 部署脚本必须包含 `NUXT_PUBLIC_API_BASE` 环境变量配置
3. 定期检查后端日志，确认没有CORS拒绝错误
4. 使用 `pm2 env <id>` 检查进程的环境变量是否正确加载

### 问题B：用户名密码错误（2026-06-20）

**问题描述：**
- 修复CORS问题后，登录按钮可以正常提交请求
- 但提示"用户名或密码错误"
- 后端API能正常接收请求，但认证失败

**排查过程：**
1. **后端日志检查** - 后端日志没有显示认证相关错误，说明请求正常到达
2. **认证逻辑分析** - `auth.service.ts` 中使用 `bcrypt.compare()` 验证密码
3. **用户初始化检查** - `NODE_ENV=production` 时，`createInitialUsers()` 虽然会被调用，但 `init-users` 接口被禁用
4. **密码哈希验证** - `createInitialUsers()` 中用户已存在时只更新角色信息，不重置密码
5. **数据库检查** - 数据库中用户记录存在，但密码可能不匹配

**根本原因：**
1. **密码未正确初始化** - 由于生产环境下 `NODE_ENV=production`，用户初始化可能被跳过或部分执行
2. **bcrypt哈希不匹配** - 数据库中存储的密码哈希与预期密码（`123456` / `admin123`）不匹配
3. **初始化逻辑问题** - `createInitialUsers()` 中，用户已存在时只更新角色信息，不会重置密码：
   ```typescript
   if (existing) {
     // 用户已存在，只更新角色信息，不修改密码！
     await this.prisma.user.update({
       where: { username: u.username },
       data: {
         realName: u.realName,
         teamCode: u.teamCode as any,
         role: u.role as any,
         roles: u.roles as any,
       },
     });
     logger.log(`${u.username}: 用户已存在，跳过密码重置`);
   }
   ```
4. **可能的场景** - 数据库重建、迁移、或手动修改用户数据后，密码字段被清空或修改

**解决方案：**

**步骤1：创建密码重置脚本**
创建 `backend/reset-passwords.js`：
```javascript
const { PrismaClient } = require('@prisma/client');
const bcrypt = require('bcrypt');
const prisma = new PrismaClient();

async function resetPasswords() {
  const hashedPassword123 = await bcrypt.hash('123456', 10);
  const hashedPasswordAdmin = await bcrypt.hash('admin123', 10);

  const usersToReset = [
    { username: 'gogotb', password: hashedPassword123, realName: '系统管理员' },
    { username: 'supervisor', password: hashedPassword123, realName: '船舶政委' },
    { username: 'shore_crew', password: hashedPasswordAdmin, realName: '船工主管' },
    { username: 'ship_political', password: hashedPasswordAdmin, realName: '船舶政委' },
  ];

  for (const u of usersToReset) {
    const existing = await prisma.user.findUnique({ where: { username: u.username } });
    if (existing) {
      await prisma.user.update({
        where: { username: u.username },
        data: { password: u.password, realName: u.realName },
      });
      console.log(`${u.username}: 密码已重置`);
    } else {
      await prisma.user.create({
        data: {
          username: u.username,
          password: u.password,
          realName: u.realName,
          teamCode: 'team2',
          role: u.username === 'gogotb' ? 'admin' : 'ship_political_instructor',
          roles: u.username === 'gogotb' 
            ? ['admin', 'shore_crew_supervisor', 'ship_political_instructor']
            : ['ship_political_instructor'],
        },
      });
      console.log(`${u.username}: 用户已创建`);
    }
  }

  // 验证密码
  for (const u of usersToReset) {
    const user = await prisma.user.findUnique({ where: { username: u.username } });
    if (user) {
      const expectedPassword = u.password === hashedPassword123 ? '123456' : 'admin123';
      const isValid = await bcrypt.compare(expectedPassword, user.password);
      console.log(`${u.username}: 密码验证 ${isValid ? '通过' : '失败'}`);
    }
  }

  await prisma.$disconnect();
}

resetPasswords().catch(console.error);
```

**步骤2：上传并执行脚本**
```bash
# 通过scp上传脚本到服务器
scp backend/reset-passwords.js root@106.14.57.62:/www/wwwroot/nav-log-system/backend/

# SSH到服务器执行
ssh root@106.14.57.62
cd /www/wwwroot/nav-log-system/backend
NODE_ENV=production node reset-passwords.js
```

**步骤3：重启后端服务**
```bash
pm2 restart nav-log-backend
```

**默认账号信息：**
| 用户名 | 密码 | 角色 | 说明 |
|--------|------|------|------|
| gogotb | 123456 | admin | 系统管理员（多角色） |
| supervisor | 123456 | ship_political_instructor | 船舶政委 |
| shore_crew | admin123 | shore_crew_supervisor | 船工主管 |
| ship_political | admin123 | ship_political_instructor | 船舶政委 |

**解决结果：** ✅ 密码重置成功，用户可以正常登录

**避免措施：**
1. **改进初始化逻辑** - 在 `createInitialUsers()` 中添加密码验证，如果密码不匹配则重置：
   ```typescript
   if (existing) {
     const isPasswordValid = await bcrypt.compare(u.plainPassword, existing.password);
     if (!isPasswordValid) {
       await this.prisma.user.update({
         where: { username: u.username },
         data: { password: u.password },
       });
       logger.log(`${u.username}: 密码已重置`);
     }
   }
   ```
2. **添加密码检查脚本** - 定期运行密码验证脚本，确保所有测试账号密码正确
3. **数据库迁移注意** - 任何数据库迁移或重建后，必须运行密码重置脚本
4. **环境变量管理** - 确保 `NODE_ENV` 设置正确，生产环境也要能初始化用户（但 `init-users` 接口保持禁用）
5. **密码安全** - 生产环境应使用强密码，并在首次登录后强制修改

### 问题1：登录提示"用户名或密码错误"（历史问题）

**问题描述：**
- 前端页面登录时，输入正确的账号密码
- 一直提示"用户名或密码错误"

**排查过程：**
1. 检查数据库 - 有用户数据
2. 直接调用后端API - 登录成功，返回token正常
3. 检查前端代码 - 逻辑正确
4. 最终发现问题：CORS跨域和端口不匹配

**根本原因：**
- 后端CORS只允许 `http://localhost:3001`
- 但实际前端运行在 `http://localhost:3000`
- 导致跨域请求被浏览器拦截

**解决方案：**

1. 修改后端 `src/main.ts`：
```typescript
app.enableCors({
  origin: ['http://localhost:3000', 'http://localhost:3001', 'http://localhost:3002'],
  credentials: true,
});

const port = process.env.PORT || 3002;
```

2. 前端 `nuxt.config.ts` 确认API地址：
```typescript
runtimeConfig: {
  public: {
    apiBase: 'http://localhost:3002/api',
    appName: '熊猫笔记',
  },
}
```

**解决结果：** ✅ 登录功能正常

### 问题2：未登录时侧边栏仍然显示

**问题描述：**
- 访问登录页面时，左侧的菜单仍然可见
- 未登录用户可以点击菜单项

**排查过程：**
1. 检查 `layouts/default.vue` - 菜单没有根据登录状态显示/隐藏
2. 检查路由中间件 - 缺少认证中间件

**解决方案：**

1. 创建 `middleware/auth.global.ts`：
```typescript
export default defineNuxtRouteMiddleware((to) =&gt; {
  const authStore = useAuthStore();
  
  authStore.checkAuth();
  
  if (to.path !== '/login' &amp;&amp; !authStore.isAuthenticated) {
    return navigateTo('/login');
  }
  
  if (to.path === '/login' &amp;&amp; authStore.isAuthenticated) {
    return navigateTo('/');
  }
});
```

2. 修改 `layouts/default.vue`：
```vue
&lt;template&gt;
  &lt;div class="min-h-screen flex flex-col"&gt;
    &lt;slot v-if="!authStore.isAuthenticated" /&gt;
    &lt;template v-else&gt;
      &lt;!-- ... 完整界面 ... --&gt;
    &lt;/template&gt;
  &lt;/div&gt;
&lt;/template&gt;
```

**解决结果：** ✅ 未登录时只显示登录页面，已登录显示完整界面
