### 2.2 技术架构对比（详细版）

| 维度 | 熊猫笔记（现状） | 飞书/钉钉 | 泛微OA | Monday/Notion | 行业标准建议 | 差距评估 |
|-----|----------------|----------|--------|--------------|-------------|---------|
| **后端架构** | NestJS 单体（模块化良好） | Go 微服务集群（数百服务）+ 服务网格 | Java 单体 + 插件扩展架构 | Node.js 微服务（Notion用Python/Go） | 模块化单体 → 微服务演进 | ⭐⭐⭐（基础合格，缺少微服务基础设施） |
| **前端架构** | Nuxt 3 SSR/CSR 混合 | 原生APP + Web 多端 + 小程序 | Vue/Angular SPA + 低代码 | React SPA + 自研Block引擎 | Nuxt 3 是合理选择，需完善工程化工具链 | ⭐⭐⭐（框架选对了，但工程化工具链缺失） |
| **数据库** | PostgreSQL 单库 | MySQL + Redis + ClickHouse 多源 | Oracle/MySQL + 缓存层 | PostgreSQL + ElasticSearch | PostgreSQL 主库 + Redis 缓存 + 分析库可选 | ⭐⭐⭐（选型正确，缺少缓存/分析配套） |
| **ORM 选择** | Prisma 5 | 自研/混合 | 自研 ORM | Prisma + 自研 | Prisma 是现代化选择，但需补全迁移链 | ⭐⭐⭐⭐（选型优秀，但缺少迁移版本管理） |
| **缓存层** | ❌ 完全缺失 | Redis 多层缓存（本地+分布式+CDN） | Redis/Memcached | Redis + CDN | 必须补齐 Redis 缓存层 | ⭐（缺失严重，高频查询性能瓶颈） |
| **消息队列** | ❌ 完全缺失 | RocketMQ/Kafka（亿级消息） | 内部消息总线 | Kafka | 至少补齐 BullMQ/Redis Queue | ⭐（缺失严重，AI/文件任务同步阻塞） |
| **搜索引擎** | ❌ LIKE 查询 | ElasticSearch（亿级索引） | ElasticSearch + 全文索引 | ElasticSearch | 短期用PG FTS，长期考虑 Meilisearch/ES | ⭐⭐（关键字搜索可接受，但无法支持复杂检索） |
| **实时通信** | Socket.IO 基础实现 | WebSocket + 长连接 + 消息确认 | 长连接 + 推送服务 | WebSocket + CRDT | 缺少断线重连、消息可靠投递 | ⭐⭐（框架存在，但能力未释放） |
| **CDN/静态资源** | 服务器直出 | 全球CDN加速 | 静态资源CDN | Cloudflare | 建议对接 OSS/七牛/Cloudflare | ⭐⭐（基础可用，速度可优化） |
| **容器化** | ❌ 仅规划 | Kubernetes（原生云部署） | Docker 支持 | Kubernetes | 先补齐 docker-compose 生产可用 | ⭐（缺失，部署效率低） |
| **部署方式** | 宝塔面板 + PM2 手动 | CI/CD 全自动化 | 私有化部署向导 | SaaS自动部署 | 至少实现 GitHub Actions 一键部署 | ⭐⭐（手动操作多，部署风险高） |
| **多租户能力** | ❌ 单实例逻辑隔离 | ✅ SaaS 多租户物理隔离 | ✅ 支持多组织 | ✅ 原生支持 | 当前逻辑隔离可接受，但需加强隔离安全 | ⭐⭐（逻辑隔离可满足当前规模） |
| **API 网关** | ❌ 无（Nginx 反向代理作为网关） | 自研多租户网关 | 独立网关服务 | API Gateway + Rate Limiting | 短期可用 Kong/Envoy 或继续用 Nginx | ⭐⭐（Nginx 够用，但缺少限流/鉴权统一处理） |

### 2.3 权限与安全对比（详细版）

| 维度 | 熊猫笔记（现状） | 飞书/钉钉 | 泛微OA | 行业标准要求 | 差距评估 |
|-----|----------------|----------|--------|-------------|---------|
| **认证方式** | JWT + bcrypt 密码 | OAuth2.0 + SSO + 多因素 + 生物识别 | AD/LDAP/SSO + 证书 | ✅ 至少支持 OAuth2.0 / SSO | ⭐⭐（基础认证合格，缺少企业级SSO） |
| **授权模型** | RBAC + 菜单级 | RBAC + ABAC + 数据权限 + 字段级 | RBAC + 组织架构权限树 | ✅ RBAC + 数据隔离 + 字段级控制 | ⭐⭐（角色级已达标，缺少字段/数据级） |
| **数据隔离** | team_code 逻辑隔离 | 组织级物理隔离 + 行级安全（RLS） | 组织/部门逻辑隔离 | ✅ 团队级独立命名空间 | ⭐⭐⭐（逻辑隔离合理，但缺少RLS） |
| **密码加密** | bcrypt（已验证） | bcrypt + 加盐哈希 + HSM硬件加密 | SHA256 + 加盐 | ✅ bcrypt/Argon2（推荐Argon2更现代） | ⭐⭐⭐⭐（bcrypt 已达标，考虑升级 Argon2） |
| **密钥管理** | ⚠️ .env 明文 + 部分代码硬编码 | KMS (密钥管理服务) + HSM | 加密密钥库 + 配置中心 | ✅ KMS / HashiCorp Vault / 配置中心 | ⭐（硬编码风险高，急需治理） |
| **会话管理** | 仅 Access Token，无过期检查 | Access + Refresh Token 双机制 + 滑动过期 + 主动吊销 | Session + Token过期 + 强制下线 | ✅ 双Token机制 + 黑名单 + 强制下线 | ⭐⭐（Token过期需重新登录，体验差） |
| **操作审计** | 基础日志（部分模块） | 完整审计链（不可篡改，WORM存储） | 完整审计日志 + 操作回放 | ✅ 不可篡改审计日志（WORM） | ⭐⭐（日志存在但可删除，缺少完整性保护） |
| **敏感数据脱敏** | ⚠️ 日志中存在身份证号明文 | 严格脱敏（身份证、手机号、密码） | 字段级脱敏显示 | ✅ 敏感字段自动脱敏 + 访问审计 | ⭐（身份证号明文存储，高风险） |
| **HTTPS 配置** | 需手动配置，默认HTTP | 默认强制 HTTPS + HSTS + OCSP | 默认HTTPS | ✅ 强制 HTTPS + HSTS + CSP | ⭐⭐（缺少CSP/HSTS，可被中间人攻击） |
| **SQL 注入防护** | Prisma 参数化查询 | 多层防护 + WAF + 输入验证 | 存储过程封装 + 输入过滤 | ✅ ORM 参数化 + WAF + 代码审计 | ⭐⭐⭐（Prisma 已防注入，缺少 WAF） |
| **XSS 防护** | ⚠️ 前端未明确配置 CSP | CSP + 内容扫描 + DOMPurify | HTML 过滤 + 编辑器净化 | ✅ CSP + DOMPurify + 内容安全策略 | ⭐⭐（未配置 CSP 响应头，风险较高） |
| **CORS 配置** | ⚠️ 部分硬编码 IP | 动态域名白名单 + 预检请求缓存 | 域名白名单配置 | ✅ 动态配置 + 预检 OPTIONS 缓存 | ⭐⭐（硬编码不灵活，部署后需改代码） |
| **Rate Limiting** | ❌ 无 | 多层限流（IP/用户/接口/全局） | 防刷机制 | ✅ 必须有，防暴力破解/爬虫 | ⭐（完全缺失，易被攻击） |
| **安全合规** | ❌ 无 | ISO27001 / 等保三级 / GDPR | 等保三级认证 | ✅ 至少满足等保二级 | ⭐（完全缺失合规文档与机制） |
| **漏洞扫描** | ❌ 无（无 npm audit 集成） | 自动化 CVE 扫描 + 渗透测试 | 定期安全审计 | ✅ npm audit + Snyk/Dependabot | ⭐（依赖版本可能存在已知漏洞） |

### 3.1 后端代码质量（NestJS + TypeScript）

#### 3.1.1 主入口与模块组织

**问题发现**（`backend/src/main.ts` / `app.module.ts`）：

| 问题 | 代码位置 | 影响 | 修复成本 |
|-----|---------|------|---------|
| ⚠️ CORS 硬编码 IP | `main.ts: const rawOrigins = process.env.FRONTEND_URL` | 生产环境变更需改代码 | 低 |
| ⚠️ 缺少全局异常过滤器 | `main.ts` 未注册 `AllExceptionsFilter` | 异常格式不统一，前端难处理 | 低 |

| ⚠️ 缺少 Graceful Shutdown | 进程被 kill 时可能中断写入 | 数据一致性风险 | 中 |
| ⚠️ bootstrap 职责过重 | 包含初始化数据、菜单配置等多逻辑 | 难以单元测试 | 低 |

```typescript
          ? exception.getResponse()
          : '服务器内部错误',
      timestamp: new Date().toISOString(),
      path: request.url,
      requestId: request.headers['x-request-id'],
    });
  }
}
```
