### 2.2 Excel模板规范（基于真实模板）

**模板文件**: `船员健康排查表模板.xls`  
**标准列（9列）**:
1. 序号
2. 船员姓名
3. 工号
4. 自有还是外聘
5. 身体状况
6. 精神
7. 工作态度
8. 家庭情况
9. 船舶采取的措施

**表头结构**:
- 行0：大标题（合并单元格）`"XXX"轮2026年x月底船员身体状况排查跟踪表`
- 行1：第一行表头（序号、船员姓名、工号、自有还是外聘、排查内容...）
- 行2：第二行表头（身体状况、精神、工作态度、家庭情况、船舶采取的措施）
- 行3起：数据行

### 2.3 校验规则

| 规则 | 校验方式 | 说明 |
|------|---------|------|
| 文件格式 | 规则校验 | 仅允许.xls/.xlsx格式 |
| 表头匹配 | 语义匹配 | 智能识别列名（支持变体别名） |
| 核心列检查 | 规则校验 | 必须包含：船员姓名、身体状况、精神 |
| 数据行检查 | 规则校验 | 至少1名船员数据 |
| AI容错 | 语义解析 | 表头有变体但核心列存在时自动容错 |

**语义匹配示例**：
- `船员姓名` 可匹配：姓名、名字、人员姓名
- `身体状况` 可匹配：身体健康、生理健康、身体情况、体检状况
- `精神` 可匹配：心理、精神状态、心理健康、心理状况

### 2.4 异常检测规则

正常关键词：`正常`、`良好`、`无`、`无异常`、`稳定`、空值

当填写内容**不包含**上述关键词时，标记为异常。

异常类型：
- `身体状况`异常 → 计入healthAbnormalCount
- `精神`异常 → 计入psychAbnormalCount
- `工作态度`异常
- `家庭情况`异常

### 2.5 四色看板体系

| 颜色 | 条件 | 含义 |
|------|------|------|
| 🟢 绿色 | 无异常 + 格式合规 | 全船健康 |

## 三、阶段二：AI基础能力增强（已完成 100%）

### 3.1 AI每日工作复盘

**功能**：自动抓取当日所有日程和日记，生成标准化工作总结草稿

**数据源**：
- Schedule表（当日所有日程）
- Diary表（当日所有日记）

**输出内容**：
1. 已完成事项
2. 进行中事项
3. 遗留待办
4. 次日优先级待办清单（高/中/低）

**接口**: `POST /ai-stats/daily-review`

### 3.2 AI时间统计

**功能**：按日/周维度统计各分类工作耗时占比

**统计维度**：
- 日统计：选定日期的所有日程
- 周统计：从周日开始的7天日程

**输出内容**：
- 总耗时（小时）
- 分类耗时占比（进度条可视化）
- 每个分类下的具体任务列表
- 效率诊断（自动识别时间冗余项、碎片化任务、长时间任务）

**接口**: `GET /ai-stats/time-stats?type=day|week&date=YYYY-MM-DD`

### 3.3 AI碎片记录自动归类

**功能**：自动将未归类的日记记录归类到标准分类

**分类体系**：记事、隐患问题、待办、通知、心得

**接口**: `POST /ai-stats/categorize-fragments`

### 3.4 私有知识库问答

**功能**：搜索用户私有数据（日记、经验、日程），AI整合后回答问题

**数据源**：
- Diary表（日记）
- Experience表（经验分享）
- Schedule表（日程）

**搜索方式**：模糊匹配（不区分大小写）

**输出内容**：
- 相关日记数量
- 相关经验数量
- 相关日程数量
- AI整合回答prompt

**接口**: `POST /ai-stats/knowledge-qa`

### 3.5 前端页面

| 页面 | 文件 | 功能 |
|------|------|------|
| AI工具集 | `pages/ai-tools.vue` | 三合一Tab页：每日复盘、时间统计图表、知识库问答 |

## 四、阶段三：AI自我迭代闭环（待开发）

### 4.1 设计思路

此阶段是整个系统的**核心价值**，实现"越用越准"的效果。

**不是传统意义上的模型微调**，而是：
1. 记录AI每次输出
2. 记录用户所有修改
3. 自动比对差异
4. 沉淀优化规则
5. 动态调整AI提示词

### 4.2 待实现清单

| 序号 | 功能 | 说明 | 预估工作量 |
|------|------|------|-----------|
| 1 | AIIterationLog表 | 记录AI输出+人工修改差异 | 小 |
| 2 | 差异比对引擎 | 自动识别修改类型 | 中 |
| 3 | 个人模型库 | 存储用户修正模式 | 中 |
| 4 | 提示词动态优化 | 根据历史修正调整prompt | 大 |
| 5 | 迭代效果评估 | 展示AI准确率趋势 | 中 |

### 4.3 差异类型定义

| 类型 | 说明 | 示例 |
|------|------|------|
| 统计错误 | AI统计数字与人工修正不符 | AI说5人异常，人工改为3人 |
| 分类错误 | AI归类不准确 | AI归为"待办"，人工改为"隐患" |
| 重点偏差 | AI遗漏关键信息 | 用户补充了重要备注 |
| 排版不符 | 输出格式不符合习惯 | 用户调整了报告结构 |
| 漏数据 | AI漏掉了某些记录 | 用户补充了遗漏的日程 |
| 冗余内容 | AI生成了不需要的内容 | 用户删除了多余段落 |
| 文案改写 | 用户修改了话术风格 | 将口语化改为正式文风 |

### 4.4 实施建议

1. **先收集数据**：运行1-2个月，积累足够的修改记录
2. **分析高频差异**：识别最常见的修改类型
3. **优化prompt**：针对性地调整AI提示词模板
4. **建立规则库**：将常见修正模式固化为规则
5. **持续迭代**：每月评估优化效果

## 九、技术架构要点

### 9.1 全局强制约束
1. 移动端仅录入/查看/上传，无AI计算
2. 网页端承载全部AI运算
3. 所有AI输出强制草稿化（isDraft=true），人工终审
4. 垂直层级流转，拒绝平行协作
5. 原始数据/文件永久保留，AI不篡改
6. 所有新页面沿用现有UI体系

### 9.2 Excel处理架构
```
用户上传Excel
    ↓
前置校验（规则化，非AI）
    ├─ 格式检查（.xls/.xlsx）
    ├─ 表头语义匹配
    ├─ 核心列检查
    └─ 数据行检查
    ↓
合规？
    ├─ 是 → 直接解析
    └─ 否 → AI容错解析
              ├─ 语义匹配列名
              ├─ 过滤多余行列
              └─ 标记容错备注
    ↓
统计数据生成
    ↓
存入数据库
```

### 9.3 AI输出流程
```
AI生成 → 标记isDraft=true → 用户查看 → 用户修改 → 保存定稿
                                              ↓
                                      记录修改痕迹（阶段三）
                                              ↓
                                      优化AI提示词（阶段三）
```
