## 问题1: Vue 3 &lt;script setup&gt; 中使用 JSX 语法错误

### 问题描述
在 `layouts/default.vue` 中，尝试在 `&lt;script setup&gt;` 中直接使用 JSX 语法定义图标组件，导致编译错误。

### 错误信息
```
Unexpected token, expected ","
```

### 原因分析
- Vue 3 的 `&lt;script setup&gt;` 默认不支持 JSX 语法
- 需要单独配置 JSX 支持，或使用 Vue 的渲染函数方式

### 解决方案
**不要**在 `&lt;script setup&gt;` 中使用 JSX 语法！

正确做法：
1. 在模板中使用 `v-if` 条件渲染
2. 或使用 `h()` 渲染函数

**示例（模板方式）：**
```vue
&lt;!-- 正确做法 --&gt;
&lt;span v-if="item.icon === 'calendar'"&gt;
  &lt;svg&gt;...&lt;/svg&gt;
&lt;/span&gt;
&lt;span v-if="item.icon === 'ship'"&gt;
  &lt;svg&gt;...&lt;/svg&gt;
&lt;/span&gt;
```

### 修改文件
- `frontend/layouts/default.vue`

## 问题2: 函数定义顺序导致"Cannot access before initialization"

### 问题描述
在 `pages/index.vue` 中，`calendarOptions` 引用了 `handleDateSelect`，但 `handleDateSelect` 定义在后面，导致初始化错误。

### 错误信息
```
Cannot access 'handleDateSelect' before initialization
```

### 原因分析
- `const` 和 `let` 声明存在暂时性死区（TDZ）
- 在函数定义之前引用会导致错误

### 解决方案
**始终**确保被引用的函数或变量在引用之前定义！

正确的顺序：
```typescript
// 1. 先定义被引用的函数
const handleDateSelect = (info) =&gt; { ... }

// 2. 再定义引用该函数的对象
const calendarOptions = ref({
  select: handleDateSelect,  // ✅ 正确
})
```

### 修改文件
- `frontend/pages/index.vue`

## 问题4: 布局未检查认证状态直接显示

### 问题描述
`layouts/default.vue` 在 `onMounted` 中检查认证，但未先调用 `checkAuth()` 从 cookie 恢复状态，导致即使未登录也显示了布局内容。

### 原因分析
- `authStore` 初始化时状态为空
- 需要先从 cookie 中读取已保存的 token

### 解决方案
**始终**在检查认证前先调用 `checkAuth()`！

```typescript
onMounted(() =&gt; {
  authStore.checkAuth()  // ✅ 先恢复状态
  if (!authStore.isAuthenticated) {
    navigateTo('/login')
  }
})
```

### 修改文件
- `frontend/layouts/default.vue`

```vue
.logo {
  border-radius: 50%;  /* 错误 */
}

<!-- 修复后 -->
<template>
  <div class="logo-container">
    <img src="/logo.png" class="logo" />
  </div>
</template>
<style scoped>
.logo {
  /* 只调整大小，不添加任何额外样式 */
}
</style>
```

## 问题7: v-else 没有相邻的 v-if

### 问题描述
在 `ships.vue` 中出现编译错误：
```
Error: v-else/v-else-if has no adjacent v-if or v-else-if
```

### 原因分析
- 在同一个 `<template>` 中有两个独立的 `v-if="row.editing"`
- 后面跟着 `v-else`，但 `v-else` 只能对应最近的一个 `v-if`
- 多个 `v-else` 并列使用是错误的

### 错误代码
```vue
<template #default="{ row }">
  <el-button v-if="row.editing">保存</el-button>
  <el-button v-if="row.editing">取消</el-button>
  <el-button v-else>编辑</el-button>  <!-- 错误：v-else 没有对应的 v-if -->
  <el-button v-else>删除</el-button>  <!-- 错误：多个 v-else 并列 -->
</template>
```

### 解决方案
使用 `<template v-if>` 和 `<template v-else>` 包裹相关内容！

```vue
<template #default="{ row }">
  <template v-if="row.editing">
    <el-button>保存</el-button>
    <el-button>取消</el-button>
  </template>
  <template v-else>
    <el-button>编辑</el-button>
    <el-button>删除</el-button>
  </template>
</template>
```

### 预防措施
- `v-if` 和 `v-else` 必须是相邻的兄弟元素
- 多个元素使用同一条件时，用 `<template>` 包裹
- 记住 Vue 规则：一个 `v-if` 只能对应一个 `v-else`

### 问题描述

## 开发规范总结

### Vue/Nuxt 开发规范
1. **不要**在 `<script setup>` 中使用 JSX 语法
2. **始终**确保函数/变量定义在引用之前
3. **始终**显式导入使用的组件和工具函数
4. **始终**在检查认证前先调用 `checkAuth()`
5. **v-if 和 v-else 必须正确配对**，用 `<template>` 包裹多个元素
6. **用户提供的图片只做尺寸调整，不做任何视觉修改**

### 后端开发规范
1. **始终**先运行 `npx prisma generate` 再启动后端
2. **始终**确保 DTO 定义与 Prisma schema 一致
3. **始终**先运行数据库迁移再启动服务
4. **新增模块后，必须在 app.module.ts 中注册**

### 工具使用规范
1. **修改代码时，优先使用 Edit 工具**，最小化修改范围
2. **只有在完全重写时才使用 Write 工具**
3. **修改前先用 Read 工具读取现有文件内容**
4. **修改后用 GetDiagnostics 检查错误**

### 代码变更前必读
在进行任何代码修改前，务必：
1. 阅读本文档的开发规范
2. 阅读《产品需求文档-PRD.md》
3. 阅读《快速开始.md》
4. 了解项目的整体架构和技术选型

### 修改后的检查清单
每次修改完成后，请检查：
- [ ] v-if 和 v-else 是否正确配对
- [ ] 所有标签是否正确闭合
- [ ] 组件是否正确导入
- [ ] 语法是否正确（括号、逗号、分号）
- [ ] 使用 GetDiagnostics 检查错误
- [ ] 刷新页面验证功能
- [ ] 检查控制台是否有报错
